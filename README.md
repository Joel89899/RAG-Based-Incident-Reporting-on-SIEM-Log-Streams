# From Fragmented Alerts to Actionable Intelligence

**Behaviour-anchored retrieval for incident reporting on SIEM log streams.**

A seven-stage pipeline that groups raw security alerts into incidents, extracts
what the adversary did as typed behavioural relations, and uses those behaviours
to constrain which MITRE ATT&CK techniques a retriever is allowed to return. It
runs end to end on a single consumer laptop with 4 GB of VRAM, so log data never
leaves the machine.

MSc thesis project, cyberMACS Erasmus Mundus Joint Master (SRH Berlin University
of Applied Sciences / Kadir Has University).

---

## The idea in one paragraph

Retrieval-augmented generation over a technique catalogue is an open-domain
similarity search: a short query is matched against 691 ATT&CK descriptions, and
the retriever has no notion of which techniques the observed evidence could
plausibly support. This project replaces that with a closed-set choice. A
knowledge graph, built from relations extracted from the alerts themselves,
decides which techniques retrieval may return at all. The claim under test is
that **the constraint** does the work, not the retriever and not the size of the
language model, and the repository contains the ablation that removes the
constraint while holding the scoring function fixed.

## Headline results

Technique classification on CIC-IDS-2017, over 18 scoreable communities.
"Grounded" is the KG-scoped condition; the baseline is the same model and the
same evidence with only the graph constraint removed.

| Model | Exact (grounded) | Exact (baseline) | Macro F1 (grounded) | Macro F1 (baseline) |
|---|---|---|---|---|
| Mistral-Nemo-12B | **0.833** | 0.556 | **0.400** | 0.200 |
| Qwen2.5-Coder-7B | 0.111 | 0.000 | 0.200 | 0.000 |
| Qwen2.5-3B | 0.278 | 0.000 | 0.114 | 0.000 |

Transfer to DARPA CADETS E3 host audit logs, macro-averaged over four attack
windows, with 95% bootstrap intervals. Grounded and baseline intervals are
disjoint for every model.

| Model | Grounded F1 | Baseline F1 | Δ |
|---|---|---|---|
| Mistral-Nemo-12B | 0.635 [0.54, 0.74] | 0.209 [0.16, 0.28] | +0.425 |
| Qwen2.5-Coder-7B | **0.710** [0.62, 0.80] | 0.272 [0.22, 0.31] | +0.438 |
| Qwen2.5-3B | 0.685 [0.60, 0.79] | 0.254 [0.21, 0.30] | +0.431 |

Three further findings are worth more than the headline numbers:

- **Every residual error comes from one stage.** Each model's exact-match rate
  equals its *reachability* rate, meaning the fraction of communities where an
  extracted relation bridges to the correct technique at all. Across the three
  models the reranker saw 22 communities whose candidate set contained the right
  answer and picked correctly in all 22. The 72-point spread between best and
  worst model is produced entirely at extraction, before retrieval runs.
- **Removing the constraint collapses the result.** Ranking the identical query
  embeddings against all 691 techniques gives exact match 0.000 / 0.000 / 0.056.
- **Correctness and grounding diverge.** Qwen2.5-Coder-7B has the highest
  faithfulness (0.621) and the lowest exact match (0.111). It writes
  well-evidenced, internally consistent reports about the wrong attacks, so any
  evaluation using grounding alone would rank the worst classifier first.

## What is in this repository

```
notebook_CIC-IDS/      Full pipeline on network flows, one notebook per model
notebook_DARPA/        Classification core on host audit logs, one per model
revision_scripts/      Post-hoc analyses and ablations (CPU only, no LLM)
results/               Every number reported, as saved by the notebooks
  cicids/<model>/      metrics, triples, graphs, reports, threshold sweeps
  darpa/<model>/       comparison metrics, bootstrap intervals, sweeps
  figures/             generated figures
```

Each `results/cicids/<model>/` directory contains the clustering metrics, the
extracted triples, the knowledge graph (GraphML plus node and edge CSVs), the
generated reports, the confusion matrix, the threshold sweep, and the ablation
outputs. Nothing in `results/` is regenerated by the analysis scripts except the
JSON files they are documented as writing.

## Hardware and reproducibility

Everything was run on one laptop with an **NVIDIA RTX 3050 Ti, 4 GB VRAM**. That
constraint drove several design choices, notably the six-layer embedding model
and the aggressive quantisation, and it is why the pipeline scales with the
number of *communities* rather than the number of alerts.

Decoding is deterministic: seed 42, temperature 0 for extraction and report
generation, 0.2 for the HyDE query expansion. Clustering and embedding are
deterministic by construction. Reruns should reproduce the saved results exactly
on the same hardware and library versions.

### Running the analyses (CPU, no GPU or model weights needed)

The ablations and the figure read the already-saved outputs in `results/` and
re-score them. They need neither a GPU nor the GGUF weights.

```bash
python -m venv .venv
.venv/bin/pip install torch --index-url https://download.pytorch.org/whl/cpu
.venv/bin/pip install sentence-transformers matplotlib pandas numpy
```

```bash
.venv/bin/python revision_scripts/cicids_unscoped_rerank_baseline.py
.venv/bin/python revision_scripts/cicids_multilabel_check.py
.venv/bin/python revision_scripts/cicids_preference_ablation.py
.venv/bin/python revision_scripts/make_quadrant_figure.py
```

See [`revision_scripts/README.md`](revision_scripts/README.md) for what each one
computes and which claim it supports.

### Running the full pipeline (GPU)

The notebooks need `llama-cpp-python` built with CUDA, `chromadb`, the datasets,
and the GGUF weights in `models/`. Confirm the GPU is visible first:

```bash
.venv/bin/python test.py
```

Then run the notebooks in `notebook_CIC-IDS/` and `notebook_DARPA/`. Each one is
self-contained for a single model and writes into `results/<dataset>/<model>/`.
Every code cell is preceded by a markdown cell explaining what it does, including
what each evaluation metric means and how to read the numbers it produces.

## Honest limitations

- **The alert representation is the binding constraint.** A single SYN packet to
  port 21 is identical whether it is reconnaissance, credential brute-forcing or
  beaconing. The template captures flow statistics, not payload or cross-flow
  state, so minority classes are missed by every model.
- **The evaluation is small.** 18 scoreable communities, dominated by a single
  technique, with overlapping confidence intervals. The DARPA result is the
  statistically firmer of the two and should be weighted accordingly.
- **The bridge mapping is hand-curated**, by the same author as the ground-truth
  mapping, and covers 33 techniques out of the 200+ in the relevant ATT&CK
  domains. It is one-to-many (7 network relations reach 12 identifiers, 10 host
  relations reach 21), and the preference-rule ablation shows the within-set
  choice carries essentially no curated prior, but a mapping curated blind to the
  evaluation data remains the experiment that would settle the question.
- **Grounding metrics measure semantic similarity, not factual accuracy.** No
  expert human evaluation of report quality was performed.
- **No timings are reported.** Wall-clock time was not instrumented, so the
  repository makes no throughput claim.
